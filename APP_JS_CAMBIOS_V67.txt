PERFIL DIN V66 · CAMBIOS EXACTOS EN app.js
==============================================

Estos cambios corrigen dos problemas distintos:
A) al pasar de Datos del profesor a Perfil por programa se conservaba el último
   programa visitado (por ejemplo Programa 8);
B) una restauración administrativa podía competir contra el respaldo local
   antiguo del profesor.

NO borran información ni cambian las colecciones de Firestore.

------------------------------------------------------------

Dentro de:

  }

  renderCurrentProgram();

y sustitúyalo por:

    try{await saveProfileToCloud(false)}catch(e){console.warn('Guardado previo al avance',e)}

CAMBIO 3 · NO PERMITIR REVISIÓN/IMPRESIÓN INCOMPLETA MIENTRAS HAY EDICIÓN
------------------------------------------------------------

Busque:

function reviewAvailable(){
  // Si Administración cerró la edición (o venció la fecha), el profesor puede
  // seguir consultando y generar/imprimir el estado actual de su perfil.
  return validateAll().ok || cfg.editingLocked || deadlinePassed() || submissionLockedForCurrentPeriod();
}

REEMPLAZAR POR:

function reviewAvailable(){
  const complete=validateAll().ok;

  // Mientras el perfil está habilitado para edición, no se puede pasar a
  // Revisión/impresión sin completar la captura.
  if(editingAllowed())return complete;

  // Solo en modo realmente de consulta/solo lectura se permite visualizar
  // e imprimir el estado existente aunque falte alguna respuesta.
  return complete || cfg.editingLocked || deadlinePassed() || submissionLockedForCurrentPeriod();
}

CAMBIOS ADICIONALES V67 · RESTAURACIÓN + REAPERTURA DE EDICIÓN
============================================================

Aunque restore-edit-guard.js protege la sesión sin modificar app.js, se recomienda
hacer también estos cambios permanentes en app.js cuando actualice la versión principal.

A) En profileBackupSnapshot(), antes de savedAt agregue:

    adminRestoreToken:store.adminRestoreToken||null,

B) En profileCloudPayload(), antes de updatedAt agregue:

    adminRestoreToken:store.adminRestoreToken||null,

C) En applyProfileContent(data), después de:

  store.planningByPeriod=planningByPeriod;

agregue:

  if('adminRestoreToken' in data){
    store.adminRestoreToken=data.adminRestoreToken||null;
  }

D) En restoreUserBackupBeforeCloud(), después de profileDeletionToken agregue:

  if('adminRestoreToken' in backup)store.adminRestoreToken=backup.adminRestoreToken||null;

E) En loadRemoteProfile(), después de:

  const remoteResetToken=d.profileResetToken||null;
  const backupResetToken=backup?.profileResetToken||null;

agregue:

  const remoteAdminRestoreToken=d.adminRestoreToken||null;
  const backupAdminRestoreToken=backup?.adminRestoreToken||null;
  const adminRestoreIsNew=
    !!remoteAdminRestoreToken &&
    remoteAdminRestoreToken!==backupAdminRestoreToken;

Luego cambie:

  const localIsNewer=!!backup && !explicitResetIsNew && (

por:

  const localIsNewer=!!backup && !explicitResetIsNew && !adminRestoreIsNew && (

Y cambie el final de preserveLocalAgainstEmptyCloud para que quede:

  const preserveLocalAgainstEmptyCloud=
    !!backup &&
    localHasData &&
    !remoteHasData &&
    d.deletedByAdmin!==true &&

Finalmente, en la rama remota, después de applyProfileContent(d), agregue:

Esto hace que una restauración administrativa tenga prioridad sobre una copia local
antigua cuando se vuelve a habilitar la edición.
